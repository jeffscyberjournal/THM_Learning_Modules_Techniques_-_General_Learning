### 2. Initial Triage

Inially select Web_traffic this change search bar to:
```

```
**Key observations:**

- Events (7,876)

Displays the raw log events returned by the search. This is the primary workspace for investigations, allowing analysts to review individual events, inspect extracted fields, and refine searches based on findings.
 
- Patterns

Automatically groups similar events and highlights recurring behaviour within the results. This helps identify anomalies, common attack patterns, scanning activity, or repeated requests without manually reviewing every event.
 
- Statistics

Displays aggregated results generated by commands such as stats, chart, top, rare, and timechart. Useful for summarising data, counting occurrences, grouping values, and identifying trends.
 
- Visualization

Presents statistical results as graphs and charts. Typically requires an aggregation command such as stats, chart, or timechart and is useful for identifying spikes, trends, outliers, and overall activity patterns.

For now focusing on Events (~17k web events)

**Some Useful fields:**

**client_ip**

 Identifies the source IP address making requests to the web server. This field is useful for identifying suspicious hosts, determining which IP generated the most activity, spotting scanning or attack behavior, and tracking an attacker's actions throughout the intrusion.

**user_agent**

Identifies the application, browser, script, or tool making the request. This field helps distinguish legitimate users (Chrome, Firefox, Safari, Mozilla) from automated attack tools such as curl, wget, sqlmap, Havij, or custom scripts. Unusual user agents are often strong indicators of malicious activity.

**path**
 Shows the URI or resource requested on the web server. This field reveals what the client attempted to access and can expose reconnaissance, exploitation, and post-exploitation activity. Examples include requests for sensitive files (/.env, /.git), path traversal attempts (../../etc/passwd), SQL injection payloads, webshell access (shell.php), and ransomware staging files (bunnylock.bin).

**status**
 Contains the HTTP response code returned by the server. This helps determine whether an attack succeeded or failed:

200 = Request succeeded
301/302 = Redirect
401 = Unauthorized
403 = Forbidden
404 = Resource not found
500 = Server error
504 = Gateway timeout (often seen during time-based SQL injection testing)

### 5. Trace the Attacker

Replace <ATTACKER_IP> with the identified IP.

```
sourcetype=web_traffic client_ip="<ATTACKER_IP>"
AND path IN ("/.env", "/*phpinfo*", "/.git*")
| table _time, path, user_agent, status
```

Output: Shows reconnaissance attempts against common sensitive files and information disclosure endpoints. By viewing the requested path, user agent, and HTTP status code together, we can determine:
 
- What resources the attacker targeted.
- Which tools were used (zgrab, curl, wget, Go-http-client).
- Whether access was successful or blocked.
- How the attacker's techniques evolved over time.
- /.env: An environment configuration file commonly containing passwords, API keys, database credentials, and application secrets. Requests for this file are a common reconnaissance technique because disclosure may provide immediate access to backend systems.
 
The repeated requests for /.git/config and /phpinfo.php indicate active enumeration of exposed configuration files and server information.
